# GridTwin ZA - what lives where, and how to run it

Root-versus-nodal confusion has cost time twice: two different `build_capacity.py`
under the same name, and a split builder writing to a filename the generator does
not read. This file exists so that does not happen a third time.

Last verified: 4 Oct 2026, build `2026-10-04f`, against the upload set of that day.

### Known inconsistency, unresolved

`build_hydra_split.py` writes to `nodal/hydra_central_split_draft.json`.
`build_capacity.py` reads `nodal/supply_area_split_draft.json`.
The file on disk carries the second name. Re-running the split builder today
would create a second file under the old name and the generator would keep
reading the stale one. Reconcile before regenerating the split.

### Resolved

`nodal/build_capacity.py`, the 324-line copy with no step 1b and no eskom bucket,
is absent from the 2 Oct upload set. If it ever reappears, delete it: running it
destroys the Hydra Central split and updates its own fingerprint so the damage
looks consistent.

## Running the suite - there is no single working directory

Sixteen counted harnesses, 805 checks, plus eng5 (6) and jsdom_local2
(a diagnostic dump, not counted). `validate_docs.py` checks the markdown and is
not part of the count.

Fourteen take the root as an argument; two of those default to `testroot` when
given none (validate_capacity, validate_lp). Three hardcode `testroot` and ignore
any argument: validate_outputs, eng5, jsdom_local2.

From the directory holding `index.html` and `nodal/`:

```
node ../validate_lint.js .
node ../validate_structure.js .
node ../validate_geo.js .
node ../validate_capacity.js .
node ../validate_inputs.js .
node ../validate_findings.js .
node ../validate_invariants.js .
node ../validate_response.js .
node ../validate_weather.js .
node ../validate_lp.js .
node ../validate_consistency.js .
node ../validate_benchmarks.js .
node ../validate_external.js .
node ../validate_solve.js .
python3 ../audit.py index.html
```

From the parent of that directory, which must be named `testroot`:

```
node validate_outputs.js testroot    # hardcodes path.resolve('testroot')
node eng5.js                         # hardcodes testroot/index.html
node jsdom_local2.js                 # hardcodes testroot/index.html
```

`jsdom_local2.js` exits 0 regardless of what it finds. Read its output, do not
check its exit code. Two `ctx.createPattern` errors (index.html:11951 on
2 Oct) are jsdom lacking canvas, not a regression.

Node dependencies: `jsdom`, `highs`, `eslint` (validate_lint calls `npx eslint`).

Expected on 4 Oct 2026: 804/805, the one failure EDMSA Scenario A CO2 2035,
known and standing. eng5 6/6.

## Per-session upload set

Project knowledge is injected as text and never reaches the filesystem, so
nothing runnable can live there. Upload each session:

```
index.html
profiles.json
ESK19679.csv               local only, never committed
a zip of nodal/            directories do not survive upload individually.
                           Rebuild it from the current folder each time: on 2 Oct
                           the zip carried a stale profiles_offshore_regional.json
                           with no licence field.
the harnesses              15 validate_*.js, audit.py, validate_docs.py,
                           eng5.js, jsdom_local2.js
build_capacity.py          the root copy
build_demand_2026.py       the root copy
```

Then run the full suite before any change.

Never commit the upload zip or ESK19679.csv. Both belong in .gitignore.
